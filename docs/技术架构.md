# 技术架构设计

## 1. 技术栈选型

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 语言 | C# | 静态类型、Windows 桌面开发一等公民、单文件部署成熟 |
| UI 框架 | WinForms | 轻量、原生 Win32 封装完善，悬浮窗/穿透/托盘/通知均有成熟 API |
| 目标框架 | .NET Framework 4.8 | **Windows 10/11 系统内置**，程序零运行时依赖，exe 仅 1~2 MB，双击即用 |
| 编译方式 | .NET 8 SDK + SDK 风格 csproj | 现代项目结构、`dotnet build` 一键编译；通过 NuGet 引用 `Microsoft.NETFramework.ReferenceAssemblies` 编译 net48，无需安装旧版 targeting pack |
| 图表 | 自绘 GDI+ 折线图 | 走势图需求简单（折线+虚线+标注），自绘零依赖、体积最小 |
| 数据存储 | JSON 文件（`Documents\DeepSeek余额监控\`） | **用户已确认**：数据存在「我的文档」，普通用户可直观查看、手动备份 |
| 密钥保护 | Windows DPAPI（`ProtectedData`） | 系统级加密，无需自定义加密算法，无需口令 |
| 安装包 | Inno Setup 脚本编译 | 免费、脚本化、可生成桌面/开始菜单快捷方式，支持开机自启注册 |
| 自动更新 | 无 | 个人小范围使用，版本迭代手动分发安装包 |

**否决的方案**：Electron（>100MB 体积）、Python+PyInstaller（体积大、启动慢）、Tauri（需 Rust 工具链，构建复杂）、.NET 8 自包含（60MB+，违背小巧原则）。

## 2. 余额数据来源

余额数据来自各供应商官方公开接口。以默认供应商 DeepSeek 为例：

```
GET https://api.deepseek.com/user/balance
Authorization: Bearer <API Key>
```

响应示例：

```json
{
  "is_available": true,
  "balance_infos": [
    { "currency": "CNY", "total_balance": "110.00",
      "granted_balance": "10.00", "topped_up_balance": "100.00" }
  ]
}
```

- 取 `balance_infos` 中 `currency == "CNY"` 项的 `total_balance`；**只显示人民币**（用户已确认），界面统一使用 ¥ 符号
- 认证失败（401 / 40002 / 40003）→ 判定为「异常」状态，悬浮窗显示橙色
- 该接口无需登录 Cookie，仅凭 API Key，安全且稳定

余额来源现已支持 **4 家供应商**（适配器层见 4.6），全部为各自官方公开接口：

| 供应商 | 接口 | 余额字段 | 说明 |
|--------|------|----------|------|
| DeepSeek | `GET /user/balance` | `balance_infos[].total_balance`（CNY） | 默认供应商 |
| OpenRouter | `GET /api/v1/credits` | `total_credits - total_usage` | 需 Management Key |
| Moonshot | `GET /v1/users/me/balance` | `data.available_balance` | |
| Z.ai | `GET /api/paas/v4/balance` | `data.available_balance` | |

## 4. 核心设计

### 4.1 状态机（BalanceMonitor）

```
                 ┌──────────────┐
    ┌───────────▶│   Normal     │◀─────────────┐
    │            │  (绿色)      │              │
    │            └──────┬───────┘              │
    │  余额 < 阈值       │    余额 ≥ 阈值        │
    │                   ▼                      │
    │            ┌──────────────┐              │
    │            │   Low        │───告警触发───▶│
    │            │  (红色)      │    (仅一次)    │
    │            └──────┬───────┘              │
    │                   │                      │
    │  查询异常          ▼                      │
    └────────────┌──────────────┐              │
                 │   Error      │───(余额保持)──┘
                 │  (橙色+⚠)    │
                 └──────────────┘
```

- 每次成功查询后写入历史记录（相同余额自动去重）
- 消费突增判定：今日消费 > 近 7 天日均 × 3（历史记录中相邻两次余额之差求和）

### 4.2 悬浮窗

- `FormBorderStyle=None` + `WS_EX_TOPMOST`（置顶）、`WS_EX_TRANSPARENT`（点击穿透）、`WS_EX_TOOLWINDOW`（不占任务栏）
- 拖动：捕获左键按下记录偏移，移动时更新 Location，松手后持久化
- 两档亮度：鼠标进入/离开时调整 `Opacity` 与背景色
- 颜色：绿 `#2E9E4F` / 红 `#D64545` / 橙 `#E8930C`，色弱友好加深字色

### 4.3 刷新与并发

- 刷新间隔 6 档（5s/15s/30s/1min/2min/5min——按需求"5秒~2分钟六档"设计为 5/15/30 秒、1/2/3 分钟）
- 每次刷新串行执行，前一请求未返回时跳过本轮（防堆积）；`CancellationToken` 支持退出时中断
- 网络异常指数退避：连续失败后拉长间隔至 30s，成功即恢复

### 4.4 数据模型

```json
// 余额记录.json
{ "records": [ { "time": "2026-08-05 18:30:00", "balance": 123.45 } ] }
```

**已确认的默认设置**：预警阈值默认 ¥10；币种仅人民币。

- 记录仅存「余额+时间」，变动额由相邻记录计算，避免冗余
- 文件 ≤ 5000 条时截断（保留最近），控制体积

### 4.5 通知

- 默认托盘气泡通知（`NotifyIcon.ShowBalloonTip`），零依赖
- 通知开关统一由设置控制，余额不足告警与消费突增告警可分别开关

### 4.6 多账户模型

**账户与配置**：一个被监控账户用 `AccountConfig` 表示（`Id` / `Name` / `ProviderId` / `ApiKey` / `WarnThreshold`），同一供应商可配置多个账户。`Config.Accounts` 保存全部账户，`Config.ActiveAccountId` 表示悬浮窗当前显示哪个账户；预警阈值从全局移入每个账户。老版本单密钥配置首次加载时自动迁移为「默认账户」并落盘新格式。

**供应商适配器（Core/Providers/）**：`IBalanceProvider` 定义统一余额接口（`GetBalanceAsync(apiKey)` 返回归一化 `AccountBalance`），`ProviderRegistry` 集中登记 4 家适配器（DeepSeek / OpenRouter / Moonshot / Z.ai），按 Id 查找。各适配器把鉴权失败、网络错误、解析失败统一映射为 `BalanceQueryException` 的错误分类。新增供应商 = 实现接口一个类 + 注册一行，调用方零改动。

**监控调度（每账户 Timer）**：每个账户一个 `BalanceMonitor` 实例（自带 WinForms `Timer` 轮询、串行防重入、连续失败退避、三态状态机）。`MonitorCoordinator` 统一管理 `List<BalanceMonitor>` 的生命周期，聚合各实例的 `StateChanged` 事件，按 `ActiveAccountId` 提供 `Current`；`Start/Stop/SetInterval/RefreshNow` 广播给全部账户。

**当前账户切换**：托盘右键「账户」子菜单列出全部账户（多于 1 个时显示），勾选当前账户，点击即调用 `AppContext.SwitchAccount` 写入 `ActiveAccountId`，悬浮窗、托盘、统计面板、告警随之刷新。

**按账户隔离**：历史记录带 `accountId` 字段，`HistoryStore` 按账户过滤/去重/消费统计，旧记录自动归属迁移账户；`AlertEngine` 按账户维护「低余额 / 消费突增」状态（含首次观察不提醒），各账户互不干扰；统计面板所有数据源按当前账户过滤。

**空账户列表**：无任何账户时悬浮窗显示「未配置账户」（灰色），托盘显示默认图标并提示「未配置账户」；在设置中配置首个账户后自动开始监控。

## 5. 安全与隐私

- API Key 仅保存在本机，DPAPI 加密后落盘，不上传任何第三方
- 无任何遥测、无自动更新、无外部 CDN
- 日志不含 API Key（查询时只记录状态码与耗时）

## 6. 兼容性

- 目标：Windows 10 / 11（x64、x86 均兼容）
- .NET Framework 4.8 系统内置，无需安装任何运行时
