# 多账户余额监控 —— 设计文档

日期：2026-08-17
状态：已确认（用户批准）
参考实现：dsh-usage-stats 的适配器方案（`lib/balance.js` / `lib/accounts.js`）

## 背景与目标

当前 DeepSeek 余额监控仅支持单个 DeepSeek 账户。目标是将余额查询扩展为**多账户并行监控**：

- 一个供应商可配置多个账户（如两个 DeepSeek Key）
- 支持多种供应商（DeepSeek / OpenRouter / Moonshot-Kimi / Z.ai）
- 悬浮窗始终显示一个当前账户，通过托盘菜单切换
- 历史记录单文件保存，按账户过滤
- 配置向后兼容，老用户升级不丢数据

## 已确认的关键决策

1. **账户切换交互**：托盘右键菜单「账户」子菜单列出所有账户，勾选当前账户，点击切换悬浮窗显示。
2. **历史存储**：单文件 + 记录带 provider 字段（`余额记录.json`）。
3. **设置窗口**：账户管理区采用「左侧账户列表 + 右侧编辑区」。
4. **账户粒度**：同一供应商可配置多个账户，账户 id 为主键，供应商只是属性。

## 1. 核心架构：适配器层（Core/Providers/）

### 归一化余额模型

```csharp
public class AccountBalance
{
    public bool IsAvailable { get; set; }          // 账户是否可调用 API
    public decimal? Remaining { get; set; }        // 剩余可用余额
    public decimal? Used { get; set; }             // 已用（部分供应商提供）
    public decimal? Total { get; set; }            // 总额度（部分供应商提供）
    public decimal? Granted { get; set; }          // 赠送额度
    public decimal? ToppedUp { get; set; }         // 充值额度
    public string Currency { get; set; } = "CNY";  // 币种
}
```

### 适配器接口

```csharp
public interface IBalanceProvider
{
    string Id { get; }                    // "deepseek" / "openrouter" ...
    string DisplayName { get; }           // "DeepSeek" / "OpenRouter" ...
    string BaseUrl { get; }               // 如 https://api.deepseek.com
    Task<AccountBalance> GetBalanceAsync(string apiKey);
}
```

### 注册表

```csharp
public static class ProviderRegistry
{
    static readonly Dictionary<string, IBalanceProvider> _providers;
    public static IReadOnlyList<IBalanceProvider> All { get; }
    public static IBalanceProvider Get(string id);
}
```

内置 4 家（解析逻辑照抄 dsh 已验证实现，接口均公开）：

| Provider | 接口 | 余额字段 | 说明 |
|---|---|---|---|
| DeepSeek | `GET /user/balance` | `balance_infos[].total_balance`（CNY） | 现有实现拆分 |
| OpenRouter | `GET /api/v1/credits` | `data.total_credits - data.total_usage` | 需 Management Key（不兼容普通推理 Key） |
| Moonshot/Kimi | `GET /v1/users/me/balance` | `data.available_balance` | |
| Z.ai/GLM | `GET /api/paas/v4/balance` | `data.available_balance` | |

加新供应商 = 实现接口一个类 + 注册一行，调用方零改动。

### 错误分类

保留现有 `QueryErrorKind`（AuthFailed / Network / ParseError / AccountUnavailable）。各适配器统一映射：
- HTTP 401/403 → AuthFailed
- HTTP 429 → Network（限流）
- HTTP 5xx → Network
- JSON 解析失败 → ParseError
- DeepSeek `is_available=false` → AccountUnavailable

## 2. 配置模型

```csharp
public class AccountConfig
{
    public string Id { get; set; }         // Guid，稳定主键
    public string Name { get; set; }       // 自定义名，如「工作号」
    public string ProviderId { get; set; } // "deepseek" 等
    public string ApiKey { get; set; }     // 内存明文，落盘 DPAPI 加密
    public decimal WarnThreshold { get; set; } = 10m;
}

public class Config
{
    // 现有全局设置不变：FontSize/Opacity/IdleOpacity/NotifyLowBalance/
    // NotifySurge/RefreshIntervalSeconds/AutoStart/LockMode/TopMost/
    // FloatPosition/StatsSize
    public List<AccountConfig> Accounts { get; set; } = new List<AccountConfig>();
    public string ActiveAccountId { get; set; }   // 悬浮窗当前显示哪个
}
```

注意：`WarnThreshold` 从 Config 移除，移到每个 `AccountConfig`（阈值归账户）。全局只保留通知开关。

### 配置兼容迁移

`ConfigService.Load()` 读取时若发现旧格式（`ApiKeyEncrypted` 非空且 Accounts 为空），自动迁移：
- 生成 `Accounts = [{ Name="默认账户", ProviderId="deepseek", ApiKey=解密旧密钥, WarnThreshold=旧阈值 }]`
- `ActiveAccountId = 该账户 Id`
- 下次 Save 落盘为新格式

### DPAPI

保留 `EncryptKey/DecryptKey`（ProtectedData + CurrentUser scope），改为逐账户加密存储 `ApiKeyEncrypted` 字段。明文密钥永不落盘。

## 3. 监控调度

- `BalanceMonitor` 保留轮询逻辑（串行、失败退避、三态状态机），构造函数改为接受 `(IBalanceProvider, HistoryStore, AccountConfig)`，不再直接持有 apiKey/阈值。
- 每个账户一个 `BalanceMonitor` 实例。
- 新增 `MonitorCoordinator`：
  - 管理 `List<BalanceMonitor>`
  - 统一事件 `StateChanged`（聚合各 monitor 的事件）
  - `SetInterval(int)` 广播给所有实例
  - `Start/Stop/Dispose` 管理全部
  - 单定时器驱动：每 tick 顺序 refresh 所有账户（账户数少，串行足够，避免并发堆积；`ponytail:` 账户超过 20 个时再考虑并行）。
- 悬浮窗/托盘/告警/统计统一订阅协调器事件，并按 `ActiveAccountId` 取当前账户数据。
- **空账户列表**：无任何账户时悬浮窗显示「未配置账户」提示（灰色），托盘显示默认图标；配置首个账户后自动启动监控并显示。

## 4. 历史存储（HistoryStore）

```csharp
public class BalanceRecord
{
    public DateTime Time { get; set; }
    public decimal Balance { get; set; }
    public string AccountId { get; set; }   // 账户 Id（AccountConfig.Id）
}
```

- 单文件存储，按 `(AccountId, Balance)` 去重（同一账户余额未变只刷新时间戳）
- 新增 `GetRecords(accountId)` 过滤
- `SpentSince/TodaySpent/AverageDailySpent` 加 accountId 参数（消费统计按账户隔离）
- 文件 ≤ 5000 条时截断保留最近（现有逻辑，按全局计）

## 5. UI 改造

### SettingsForm —— 账户管理区

「账户」组（在「余额提醒」之前）：
- 左侧 `ListBox`：显示各账户名
- 右侧编辑区：名称 TextBox、供应商 ComboBox（4 家）、密钥 TextBox（UseSystemPasswordChar + 显示开关）、预警阈值 NumericUpDown、测试/应用/删除按钮
- 新增/删除账户、切换选中项即时保存
- 原「余额提醒」组的阈值 NumericUpDown 移除，阈值并入账户编辑区；保留两个通知开关

### FloatingWindow

- `UpdateDisplay()` 顶部加一行小字显示账户名（如 `DeepSeek · 工作号`），余额主字不变
- 状态逻辑不变（按当前 monitor），尺寸测量需考虑账户名行

### TrayIcon

- 菜单加「账户」子菜单：每账户一项，勾选当前账户，点击切换 `ActiveAccountId` 并刷新悬浮窗
- 其余菜单（显示/设置/统计/退出）不变

### StatsForm

- 顶部加当前账户名标题
- 所有数据源过滤 `ActiveAccountId`，切换账户后自动刷新
- 走势图/表格/消费统计均按当前账户

## 实现偏差（编码完成后记录，2026-08-17）

实现与本文档的主要差异（未提及处均按设计落地）：

1. **监控调度：单定时器 → 每账户 Timer**（对应 §3）
   设计为「单定时器驱动，每 tick 顺序刷新所有账户」；实现保留每个 `BalanceMonitor` 各自一个 WinForms `Timer`，`MonitorCoordinator` 仅负责管理实例列表、聚合/广播 `StateChanged` 事件、按 `ActiveAccountId` 提供当前账户，`Start/Stop/SetInterval/RefreshNow` 广播给全部实例。
   理由（已在实现计划 Global Constraints 声明）：复用现有退避/防重入/状态机逻辑，改动面最小；账户数少，各自定时不会堆积。若未来账户数量大，可改回单定时器或引入并行调度。

2. **历史记录字段：provider → accountId**（对应「已确认关键决策 #2」）
   设计写「记录带 provider 字段」，实现为记录带 `accountId`（`AccountConfig.Id`），供应商只是账户的一个属性（与决策 #4「账户粒度」一致）。旧记录加载时自动归属迁移出的账户。

3. **告警首次观察不提醒（按账户恢复 `_initialized`）**
   多账户化改造中曾丢失「首次观察不提醒」逻辑，Task 7 按账户恢复：`AlertEngine` 用 `Dictionary<accountId, bool> _initialized` 记录各账户是否已被观察过，首次状态变化不弹「余额不足」通知，避免启动轰炸；低余额/突增状态同样按账户隔离。

4. **悬浮窗账户名行仅显示账户名**
   设计示例为「DeepSeek · 工作号」（供应商 · 账户名）；实现仅显示 `AccountConfig.Name`（设置中填写的名称），供应商名不拼入悬浮窗。
